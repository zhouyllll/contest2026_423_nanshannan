# 外设时钟上电检查表

按顺序过一遍。每一条都要有**读回或实测**作为依据，不能只写不验。

## 1. 总线时钟（PCLK / HCLK / APB）

- [ ] 门控已开
- [ ] 依据：能正常读回一个已知非零的只读寄存器（版本号、ID）
- [ ] ⚠ 读回 `0x00000000` 或 `0xffffffff` 通常就是这一层没开

> ID 类寄存器要注意**位宽**。ARM PrimeCell 的 Peripheral ID 是 8 位宽
> 寄存器（0xfe0/0xfe4/0xfe8...），某些 SoC 上 32 位读只回低字节，
> 拼接校验会误判成"不是这颗芯片"。

## 2. 功能时钟门控

- [ ] 门控已开（**和第 1 层是不同的位，常在不同的 CON 寄存器**）
- [ ] 依据：**传输计数器 / 状态机有动作**，不是寄存器回读
- [ ] ⚠ 只验证第 1 层的自检会通过，而设备是死的

判据示例：

| 外设 | 看这个 | 含义 |
|---|---|---|
| I2C | `FCNT` 已传输字节数 | 0 = 功能时钟没开 |
| 音频 | FIFO 水位 | 恒 0 = 没有采样时钟 |
| SPI | 传输完成标志 | 永不置位 = 时钟没走 |
| MMC | CMD 完成中断 | 无任何中断 = CIU 时钟没跑 |

## 3. 选源与分频

- [ ] mux 选的父时钟是哪个？**读回确认**，别信复位默认值
- [ ] 分频系数写了吗？（只开门控 = 用引导器留下的值）
- [ ] 分频编码是 `n` 还是 `n-1`？同一个头文件里两种约定常常混着
- [ ] 父时钟自己的频率验过吗？（别停在第一层）
- [ ] 改完发"更新时钟"握手了吗？
- [ ] 依据：**实测**（见 `measuring-real-rates.md`），不是算出来的

## 4. 板级外给时钟

- [ ] 查过**原理图**了吗？（不是 dtb）
- [ ] 有没有别的芯片给它供时钟（RTC 的 CLKOUT、PMIC、另一颗 SoC）
- [ ] 那个源需要显式使能吗？（HYM8563 的 CLKOUT 就需要写寄存器 0x0D）
- [ ] 依据：供方寄存器读回 + 受方能上电

> 组合无线模组（WiFi+BT）几乎都需要 32.768kHz 慢时钟才能完成上电。
> 缺它的表现不是"时钟不对"，是"模组完全没反应" —— 很容易被误判成
> 电源或复位时序问题。

## 5. 跨层一致性

- [ ] 上层软件配的比率（如编解码器的 256fs）和实际 MCLK 一致吗？
- [ ] ⚠ **两边一起错会自洽，谁都不报错。** 必须各自独立验证，
      不能用"它们对得上"当证据。
