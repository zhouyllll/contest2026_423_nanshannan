# xTS 稳定性与启动时间实测

测量脚本：`scripts/stability.sh`（可复现，非手工记录）
被测镜像：`nuttx.bin` 1044480 字节

## 1.2.1 Reboot 启动异常 / 2.1.4 Reboot 启动时间

软重启 10 次（`loader normal`：写 PMU0_GRF 的正常启动标志 + CRU 全局软复位）

| 次数 | 结果 |
|---|---|
| 成功 | **10** |
| 失败 | 0 |

| 指标 | 值 |
|---|---|
| 平均 | **4744 ms** |
| 最小 | 3422 ms |
| 最大 | 4897 ms |

十次里有一次 3422ms，比其余快约 1.5 秒。其余九次集中在 4876–4897ms，
离散度很小。这一次的差异**未做定位**，可能与引导器的分区扫描路径有关
（U-Boot 每次启动都会尝试解析 GPT 并报错），此处如实记录，不做推测性解释。

## 1.2.2 Cold boot 启动异常 / 2.1.3 Cold Boot 启动时间

经下载模式复位 5 次（`rkdeveloptool rd`，会重新走一遍完整引导器）

| 次数 | 结果 |
|---|---|
| 成功 | **5** |
| 失败 | 0 |

| 指标 | 值 |
|---|---|
| 平均 | **4795 ms** |
| 最小 | 4789 ms |
| 最大 | 4805 ms |

★ **口径说明**：板上没有可编程的断电开关，`rkdeveloptool rd` 是最接近
上电复位的自动化手段。真正的冷启动（拔插电源）需人工操作，无法进入
自动脚本，因此本项测的是「完整引导器复位」而非严格意义的上电冷启动。
两者差异主要在 DDR 初始化是否重做。这一点必须写明，不能当作等同。

启动时间从**触发复位**计起，到串口出现 `NuttShell` 为止 —— 即"从复位到
可敲命令"，包含引导器耗时，与实际使用体验一致。只计内核自身那一段会
显著偏小。

## 1.2.3 系统 RAM 资源占用

```
      total       used       free    maxused    maxfree
   66064376    3706328   62358048
```

| 项 | 值 |
|---|---|
| 堆总量 | 66,064,376 字节（63.0 MB） |
| 已用 | 3,706,328 字节（**3.5 MB**） |
| 空闲 | 62,358,048 字节（59.5 MB） |
| 占用率 | **5.6%** |

配置为 `CONFIG_RAM_SIZE=64MB`。已用 3.5MB 中包含 LVGL、帧缓冲描述、
各驱动的静态与动态分配。全屏帧缓冲（720×1280×4 = 3.5MB）由 fb 驱动
在 `up_fbinitialize()` 中分配，是这一项的主要构成。

## 1.2.4 系统 Flash 资源占用

| 项 | 值 |
|---|---|
| `nuttx.bin` | 1,044,480 字节（1020.0 KB） |
| `boot-nuttx.img` | 3,702,784 字节（3616.0 KB） |

`boot-nuttx.img` 是打包进 Android boot.img 容器后的体积，除内核外还包含
原厂保留的 ramdisk / second / dtb 各段（见 `scripts/repack-bootimg.py`），
烧写时占用 boot 分区。内核本体只有 1020 KB。
