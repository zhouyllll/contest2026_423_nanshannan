# K7 桌面视觉助手：应用设计与验收

## 用户故事

桌面工作者在离开座位前，用“你好，openvela”唤醒设备，说“帮我看看钥匙、水杯还在不在”；也可以启用离桌巡检，让设备在满足触发条件时主动检查并提醒。

## 交互闭环

1. 唤醒：麦克风持续采集短音频片段，仅在本地匹配固定唤醒词“你好，openvela”；误唤醒后超时退出，播音时暂停识别，避免回声触发。串口或触摸按钮保留为调试入口。
2. 对话：唤醒后录制一次话语，ASR 转文字送 ai_agent 消息总线，回答显示在 LVGL 界面并由 TTS 播报。凭据留在板上 `/data`，不得入仓。
3. 看摄像头：Agent 调用 `camera_capture`，由 `/dev/video0` 采集 JPEG 并发送至视觉模型。回答必须基于本次工具结果；失败时说明失败，不猜测画面。
4. 主动场景：用户设置要检查的物品及巡检开关。离桌事件优先由可验证的传感器或用户按钮触发；没有离桌传感器时采用明确告知用户的定时巡检。巡检采一帧、分析目标物品、与上次已确认状态比较；仅在高置信度变化且冷却期已过时主动提示。模糊或遮挡时不告警。
5. 提示：屏幕显示物品、状态和时间，语音播报短句；支持“知道了”“暂停巡检”“关闭巡检”。每次决策保留时间、工具结果、是否提示及原因，供演示核查。

## 代码边界

- 比赛专属仓保存场景应用、自定义 Skill、板级配置和验收记录。
- `packages/ai_agent` 提供对话、`camera_capture`、ASR/TTS、消息总线。其定时任务当前直接执行工具或直接发通知，不会把定时消息送回 Agent 推理，因此“定时拍照→识别→状态比较→选择性提醒”需要独立场景服务，不能只用 `cron_add` 冒充主动视觉判断。
- 场景服务设采集超时、串行相机访问、最短巡检间隔和提醒冷却期。视觉模型输出未知时保持上一状态，不按二值结果硬判。
- `/data` 当前为 tmpfs；物品列表、任务、API Key 重启后会丢失。演示前重新配置，持久化需另做存储接入。

## 阶段与通过标准

| 阶段 | 通过标准 |
| --- | --- |
| A 对话与相机 | `ai_agent` 对话成功；`camera_capture` 返回真实画面分析，5 次连续调用无泄漏或死锁 |
| B 语音 | `mic` 采样峰值随人声变化；ASR 文本正确；TTS 可听；固定唤醒词 20 次测试记录命中与误触发 |
| C 主动巡检 | 人工摆放/移走物品，状态变化时主动提示；不变、遮挡、相机断开时不乱报；关闭后不再采集 |
| D 展示 | 屏幕有清晰状态；演示“唤醒→对话→看摄像头→主动提醒→关闭”完整流程 |

## 当前事实与待验证

- 项目文档记录 MiMo 对话链路和 V4L2 JPEG 取帧已通过；不能据此推断 ASR、TTS、视觉模型或唤醒词已通过。
- 当前 `amp/defconfig` 启用 ai_agent 和 VIDEO，但未启用 `AI_AGENT_CAMERA`。
- ai_agent 有 `voice_start`/`voice_stop` 语音入口，无固定唤醒词实现；K7 麦克风仍需通过 `mic` 命令做信号验证。

## 部署与第一轮验证

1. 从 `board/kickpi-k7/configs/amp/defconfig` 重新生成固件配置并编译；仅修改 defconfig 不会改变当前 `nuttx/.config`，需确认生成后的 `.config` 有 `CONFIG_AI_AGENT_CAMERA=y`。
2. 先用项目已有的 `v4l2cap` 验证 `/dev/video0`，再在 `ai_agent` 中请求“看看桌面上有什么”，确认调用的是 `camera_capture` 且视觉模型返回本次画面描述。
3. 将本仓 `agent_skills/desk-guard.md` 复制到板上 `/data/ai_agent/skills/desk-guard.md`，重启 `ai_agent` 后确认它能读取该 Skill。当前 `/data` 为 tmpfs，每次重启须重新复制。
4. 语音先分别验证 `mic`、`voice_test_asr`、`voice_test_tts`，再连接固定唤醒词，不能跳过硬件音频验收。
5. 主动场景服务完成前，只演示被动视觉问答；不得将 `cron_add` 的普通定时提示描述为主动视觉判断。
